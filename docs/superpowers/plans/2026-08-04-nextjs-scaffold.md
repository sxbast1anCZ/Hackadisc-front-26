### Task 1: Initialize the Next.js scaffold

**Files:**
- Create (generated by `create-next-app`): `package.json`, `tsconfig.json`, `next.config.ts`, `eslint.config.mjs`, `postcss.config.mjs`, `.gitignore`, `next-env.d.ts`, `public/*`, `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`
- No files are modified; the repo currently only contains `.git/` and `docs/superpowers/`.

**Interfaces:**
- Consumes: nothing (first implementation task).
- Produces: a runnable Next.js project at the repo root, with `npm run dev`, `npm run build`, and `npm run lint` scripts available in `package.json`. Later tasks (dashboard layout, KPI components, API integration) will build inside `src/app/` and `src/components/` (not yet created).

- [ ] **Step 1: Run `create-next-app` to generate the project**

Run from the repo root (`C:\Users\David\Sites\Hackadisc-front-26`):

```bash
npx --yes create-next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --disable-git --yes
```

Flags explained:
- `.` — scaffold into the current directory (already contains `.git/` and `docs/`, which `create-next-app` allows alongside an empty-enough project).
- `--ts` — TypeScript.
- `--tailwind` — Tailwind CSS config.
- `--eslint` — ESLint config.
- `--app` — App Router.
- `--src-dir` — put app code under `src/`.
- `--import-alias "@/*"` — default alias, set explicitly.
- `--use-npm` — force npm (avoid it detecting/prompting for another package manager).
- `--disable-git` — skip git init/commit; a repo already exists here.
- `--yes` — use defaults for anything not explicitly passed, non-interactive.

- [ ] **Step 2: Verify the generated file structure**

Run: `ls -la` (or `Get-ChildItem` on PowerShell) at the repo root.

Expected: `package.json`, `tsconfig.json`, `next.config.ts`, `eslint.config.mjs`, `postcss.config.mjs`, `.gitignore`, `public/`, and `src/app/` (containing `layout.tsx`, `page.tsx`, `globals.css`) are all present. `docs/` and `.git/` are untouched.

- [ ] **Step 4: Run ESLint**

- [ ] **Step 5: Run the production build**

Run: `npm run build`

Then stop the dev server process.

`create-next-app` generates its own `.gitignore` (covering `node_modules/`, `.next/`, etc.) — since git init was skipped, this file is just a normal generated file to stage, not merged with anything pre-existing (none existed before). Verify it excludes `node_modules` and `.next`:

Run: `cat .gitignore`

Expected: contains `node_modules` and `.next` (or `/node_modules`, `/.next`) entries.

Then stage and commit everything `create-next-app` generated:

```bash

```

Confirm `git status` shows the expected new files (`package.json`, `src/`, `public/`, config files, `.gitignore`) and does **not** show `node_modules/` (it must be excluded by `.gitignore`).

```bash
git commit -m "feat: initialize Next.js 16 scaffold (TS, Tailwind, ESLint, App Router)"
```
